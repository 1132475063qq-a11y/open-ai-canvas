# 编剧参考：项目发展与修订工作流

## 来源与用途

本参考提炼自用户原始独立 `screenwriter` Skill 的工作流能力；它不取代项目权威事实、锁定 Artifact 或 Human 决定。用于从零创作、扩展已有想法、修订、诊断和改编时选择正确的编剧工作流。

## 先做输入判定

1. 记录本轮交付、媒介/体量、现有材料定位、不可违反条件和当前版本。
2. 只追问会改变本轮交付的缺口；已知信息不重复询问，每轮最多两个问题。
3. 只对不可避免且可逆的空白作“暂定”假设；主角、结局、主题、锁定事实、品牌事实、预算或范围进入 `NEEDS-YOU.md`。
4. 处理已有材料时，只读取用户指出的附件、路径或当前项目范围；不扫描无关项目，也不假装读过原作、媒体或资料。

## 五种工作流

### 从零创作

依次形成项目判断、命题、差异化故事方向、人物系统、世界规则、结构、场景/分集规划和本轮所需剧本。用户只要其中一项时，只交付该项，不自动扩展为分镜、视频提示词或完整制作包。

### 扩展已有想法

保留原概念已确认的核心价值；把它发展为 logline、人物目标与阻力、关系、因果链、结局方向及用户要求的下一项产物。多个方案必须在冲突机制、人物选择、情绪体验、叙事机制或结局上真正不同，不能只替换姓名、职业或地点。

### 修订现有剧本

先列出要保留的内容与修订边界，定位问题和根因，再做最小充分修改。跨场、跨集、结构、人物弧、因果链或整体节奏的修改，应列出受影响的角色、场景、时间线、道具、知情范围与后续情节；LOCKED 版本走 CHANGE-REQUEST 和新 object_version。

### 检查与诊断

按用户指定范围检查因果、动机、知识、时间、空间、道具、关系、节奏、台词、伏笔回收、反转公平性、主题、体量和制作可行性。每个重要问题应包含位置、证据、原因、观众/制作影响、最小修复原则，标记“必须修改 / 建议修改 / 可选优化”。独立审查任务交 `script-review`，本 Skill 不把审查结论伪装成主稿修改。

### 改编

区分原作核心与改编目标，明确保留、压缩、删减、合并、重构与影视化表达。保留主题和体验不等于复制具体情节、台词、角色名称或标志性桥段；公开发行或制作的版权/授权状态不明时，标为风险而不作断言。

## 场景与台词最低标准

- 每场至少改变目标、关系、信息或状态之一；没有功能的重复场景应删除、合并或重写。
- 动作和台词必须来自角色的当下欲望、恐惧、知识和策略；将关键场景写为 `trigger → choice → visible action → consequence → state change`。
- 台词具备行动目的，区分人物词汇、句式、停顿、回避、说谎与冲突策略；不要用解释性台词复述画面或让所有角色同一种口吻。
- 不在剧本正文中混入景别、镜头运动或模型指令；那些属于导演、提示词和制作风险域。

## 何时读取其他参考

- 需要故事梗概、分场/分集大纲、系列规划、互动分支或改编方案：`story-development.md`。
- 需要完整格式、媒介规格或长内容交付策略：`screenplay-formats.md`。
- 需要跨场修订或重构：`revision-workflow.md`。
- 需要质量体检：由 `script-review` 独立审查；必要时参考其审查结论，但不越权锁定。
